1. WHAT SYNASE AI IS
--------------------------------------------------------------------------------
SYNASE AI is an AI decision-intelligence console for software teams. A workspace
holds projects; each project ingests a repository + multimodal inputs, runs
(mocked) analysis workflows through an MCP V2 runtime, and produces two
intelligence layers:

  * PRODUCT layer  — requirements, prioritisation, strategy, roadmap
  * DEVOPS layer   — architecture, quality, security, risk, deps, testing, deploy

Outputs flow into decision reports and human-in-the-loop approvals. Everything
is currently MOCK: no model, tool, third-party API or pipeline is ever invoked.
Suggestions are always visibly separated from confirmed state ("provenance").

3. ARCHITECTURE (the "format" all new work must follow)
--------------------------------------------------------------------------------
Strict three-layer stack:

    app/          shell, router, bootstrap, single event listener  (composition root)
      |
    domain/       home · product · devops · mcp · context · outputs · integrations · work
      |
    shared/       api · state · components · services · utils · types   (leaf layer)

Logical request flow (six layers):
  Route -> Page composition -> View template -> Domain API facade
        -> Shared adapter (mock | live) -> Transport (/api/v1/...)

HARD RULES
  1. A domain NEVER imports another domain (product/ cannot import devops/ etc.).
  2. shared/ imports nothing outside itself.
  3. A domain may import app/paths.js (route table) — the only sanctioned exception.
  4. ONE router (src/app/router.js) and ONE delegated listener set
     (click/change/input/submit) in src/app/main.js.
  5. Views never attach listeners. They express intent via attributes:
       data-route="/app/..."   -> navigate
       data-action="..."       -> handled in app/main.js, mutate state, render()
       data-theme-toggle       -> shared/services/theme.js
  6. Views never call the API. app/main.js calls domain facades and writes
     results into the store; views read from `state`.
  7. Every interpolated value is escaped (escapeHtml). Use shared ui helpers.
  8. Mutating calls REQUIRE { idempotencyKey: createIdempotencyKey() }.
  9. All API methods return envelopes: { data } or { data, meta:{page,pageSize,total} }.
     Errors: ApiError { code, message, status, requestId, details }.

Historical note: old src/app.js, phase11.js, phase12.js (three racing renderers
via MutationObserver) were REMOVED and folded into the single router. Old
data-p11-*/data-p12-* attributes were normalised to data-route/data-action.
