# SYNASE AI - Frontend UI Revamp Context for Google Stitch

## OVERVIEW
This document serves as the design and architecture context for a complete UI/UX revamp of the Synase AI platform. The goal is to build a "Professional Grade", high-end visual design using modern UI principles (glassmorphism, premium dark/light mode, micro-animations) while *strictly retaining* the existing service-oriented frontend architecture and API contract.

There are 87 API endpoints defined across 15 domain modules. The new UI must map its components and interactions to these existing APIs and domain models (`src/types.d.ts`, `src/phase11-types.d.ts`, `src/phase12-types.d.ts`).

## DESIGN AESTHETIC & THEME (STITCH PROMPT)
Use high-end visual design standards. The interface should feel expensive, bespoke, and premium. 
- **Typography**: Use modern fonts like Inter, Roboto, or Outfit. No generic browser defaults. Extreme type scale contrast where appropriate.
- **Colors & Accents**: Curated, harmonious color palettes (e.g., sleek dark modes, HSL tailored colors).
  * **Strict Solid Accents Rule**: NO harsh, multi-color or distracting rainbow linear gradients on interactive elements, buttons, select triggers, or pills. All interactive accents use refined solid tones, neutral slates, or subtle translucent fills with crisp borders.
- **Curved Dropdown Architecture**:
  * Complete elimination of native boxy Windows OS comboboxes and raw `<select>` elements.
  * All dropdowns use custom curved components (`border-radius: 12px` to `16px`) with SVG chevrons, upward/downward rotation animation (`transform: rotate(180deg)`), active checkmarks, and floating elevated popovers.
  * Dual-contract preservation: Hidden `<select>` elements remain in the DOM with synced values to preserve 100% of test assertions.
- **Layout & Anti-Clipping**:
  * Asymmetric layouts, gapless bento grids for dashboards.
  * Card containers (`.p12-metric`, `.p12-panel`, `.settings-card`) use `overflow: visible; position: relative;` with individual child head/body corner radius to guarantee floating dropdown menus and tooltips never get clipped by card edges.
  * Stacking elevation via `.has-open-select` and calibrated z-index tiers (Topbar: `80`, Dropdowns: `120`, Select Popovers: `9999`).
- **Motion**: Smooth transitions, hover states, and perpetual micro-motion.
- **Elements**: No heavy muddy shadows. Use subtle borders, glass effects, and minimalist structural boundaries.

## CORE APPLICATION PAGES & API MAPPING

### 1. Authentication & Onboarding (Module 1 — Auth 4 Pro Suite)
**Visual Requirements:**
- **Strict Single-Viewport Architecture:** Entire page locks to `100dvh` (tested at 1920×991 and standard viewports) with zero vertical scroll (`scrollHeight === clientHeight`).
- **Left Art Panel (Brand Narrative & Orbital Constellation):**
  * Brand header with insignia (`SYNASE AI DECISION INTELLIGENCE`) and `← Back to Home` glassy pill navigation.
  * Commanding hero headline: `Clear engineering decisions from idea to production.` (`clamp(38px, 4vw, 54px)`) with iridescent gradient shimmer on `production.`.
  * Tracked monospace eyebrow (`ENTERPRISE DECISION PLATFORM`) and narrative description.
  * Three trust pills: `SOC 2 Type II`, `Enterprise Grade · 99.99% SLA`, `Private & Encrypted · Zero Retention`.
  * Orbital Integration Constellation: 3 concentric counter-rotating SVG orbits, glowing energy pulse particle nodes, central core disc with luminous violet aura and *"TRUSTED ENGINEERING INTELLIGENCE"* typography, and 6 floating integration nodes (GitHub, Kubernetes, Docker, Linear, Notion, Jira) with brand-calibrated hover glow and scale elevation.
  * Capability matrix: 3 numbered glass cards (`01 Code & Specs`, `02 Smart Review`, `03 Verified Action`) with squircle icon boxes and live status pills (`Code Sync: Ready`, `Analysis: Active`, `Security: Verified`).
  * Bottom boundary is clean and evenly spaced without cramping quote boxes, allowing generous typography scaling.
- **Right Panel (Authentication Card):**
  * Double-bezel glassmorphic card (`rgba(12, 14, 22, 0.94)`) with animated 2px top-edge gradient shimmer beam (`topBorderShimmer`).
  * Segmented mode switcher (`Sign in` / `Create account`) with active royal-slate pill styling.
  * Dual Enterprise OAuth SSO buttons (`GitHub` and `Google SSO`).
  * Interactive credentials form with left-aligned icons, client-side validation, and interactive password visibility toggler (`[data-toggle-password]`).
  * High-contrast crisp white CTA button (`Sign in to Workspace →`) with kinetic hover bloom.
  * Direct Sandbox Workspace entry (`▶ Direct Demo Workspace Entry (ABESIT / Platform Prj) →`).
**Key Interactions:**
- Login: `POST /api/v1/auth/login` (API-01)
- Register: `POST /api/v1/auth/register` (API-02)
- Recover: `POST /api/v1/auth/recover` (API-03)
- Instant Demo Access: `data-action="demo-login"` bypassing credentials to launch platform workspace directly
- Enterprise OAuth Simulation: `data-sso="github"`, `data-sso="google"`
- Password Toggle: `[data-toggle-password]` toggling password mask & eye icons
- Architecture Desk Inquiry: `POST /api/v1/contact` (landing & auth footer link)

## INTEGRATION RULES
1. **Component Interfaces:** Components must consume the Domain models provided in `src/types.d.ts` without attempting to alter the data structures.
2. **Service Delegation:** All network calls, loading states, and error handling should be delegated to the existing service instances (`api`, `phase11Api`, `phase12Api`).
3. **Idempotency:** Any form submissions (creations, approvals) must pass an `idempotencyKey` as expected by the mutating endpoints.
4. **DOM Integrity:** Any MutationObservers must have robust content guards to prevent infinite loops.
