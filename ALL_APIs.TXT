1. ARCHITECTURAL CONVENTIONS & ENVELOPE SPECIFICATIONS
================================================================================

1.1 RESPONSE ENVELOPES
----------------------
All API responses adhere strictly to canonical domain envelopes:

Single Entity Success Envelope:
{
  "data": { ... }
}

Paginated List Envelope:
{
  "data": [ ... ],
  "meta": {
    "page": 1,
    "pageSize": 25,
    "total": 42
  }
}

1.2 ERROR ENVELOPE & CANONICAL CODES
------------------------------------
Errors are normalized with unique request identifiers and canonical codes:
{
  "code": "RESOURCE_NOT_FOUND" | "IDEMPOTENCY_REQUIRED" | "INVALID_CONTEXT_REFERENCE" | ...,
  "message": "Human-readable description of error.",
  "status": 400 | 401 | 403 | 404 | 408 | 409 | 500 | 502 | 503,
  "requestId": "req_XXXXXXXX",
  "details": { ... }
}

1.3 IDEMPOTENCY POLICY & MUTATION SAFETY
----------------------------------------
- All mutating calls (creation, uploads, connections, report generation, approvals, comments)
  REQUIRE an `idempotencyKey` option (passed as a parameter or via `X-Idempotency-Key`).
- Omitting the idempotency key causes an immediate rejection (`IDEMPOTENCY_REQUIRED`).
- Replaying a request with an existing idempotency key deterministically returns the exact
  same saved receipt without re-executing or altering state.

1.4 MOCK SAFETY GUARANTEES & NON-EXECUTION SEMANTICS
---------------------------------------------------
- Zero External Requests: No third-party API (GitHub, Jira, Slack, OpenAI, Anthropic, etc.) is contacted.
- Zero Execution: No code is executed, no repositories are committed to, no pipelines are triggered.
- Approval != Execution: Approval states (approved/rejected) strictly represent recorded human intent
  and explicitly carry `executed: false` and `downstreamActionsExecuted: false`.
- Activity != Audit: Operational activity logs are mutable business events; audit records are immutable,
  security-grade projections with cryptographic redaction.

1.5 HEADER & TRANSPORT SECURITY
-------------------------------
All requests and fixtures undergo recursive redaction before exposure:
- [REDACTED]: `authorization`, `cookie`, `credential`, `password`, `secret`, `token`, `api_key`, `client_secret`
- [OMITTED]: `requestBody`, `responseBody`, `rawPayload`, `headers`

   - Submitting valid credentials (e.g. `alex.turner@company.com`) calls `POST /api/v1/auth/login` (API-01).

   - Clicking either SSO button (`data-sso="github"`, `data-sso="google"`) displays an enterprise simulation toast notification and redirects to workspace within 600ms.
